# Email tools — operational guide (himalaya IMAP/SMTP)

Load this doc (`dome_load_doc({ id: "email_tool" })`) before any `email_*` tool call.

## Prerequisites
- User must connect at least one account in **Settings → Email** (IMAP + SMTP, app password for Gmail/Outlook/iCloud/Zoho).
- Tools use the **default account** unless `account_id` is added in a future version.
- If no account: return a clear error — do not claim email is unavailable without calling the tool.

## Tool map
| Tool | Action | Notes |
|------|--------|-------|
| `email_list_folders` | List folders | Call before browsing non-INBOX folders |
| `email_list` | List envelopes in folder | Default folder INBOX; pagination `page`, `page_size` (default 30) |
| `email_search` | Search mailbox | Requires `query`; himalaya filter syntax or plain words |
| `email_read` | Full message body | Needs `message_id` from list/search; plain text returned (HTML stripped) |
| `email_send` | Send new mail | **HITL approval** in Many; also blocked if agent send permission is off |
| `email_reply` | Reply to message | **HITL approval** in Many; threading derived from original |

## Parameters (IPC-backed)
- **Folders**: standard names INBOX, Sent, Drafts, Trash, etc. (provider-specific).
- **Send/reply**: plain-text `body`; `to` comma-separated; optional `cc`, `bcc`, `subject` (send only).
- **Errors**: `app_password_required`, `auth_failed`, `connection_failed` — tell user to fix Settings → Email.

## Agent permissions
Per-account toggles in Settings → Email restrict what **Many / agent chat** may do (`list`, `read`, `search`, `send`, `reply`).
Workflows and automations bypass these toggles (implicit approval).

## Flow
1. If **mentioned-sources** lists an `email`, call `email_read` first (`message_id` = pin id or `meta.uid`, `folder` from meta). Do not claim the mailbox is empty before this.
2. To find **mail the user sent** to that person: `email_list_folders` if needed, then `email_search` with `folder` set to the Sent folder (or provider equivalent from `email_list_folders`). Query = the other party’s address from the pinned message `From` / `To`. Prefer `Message-ID` / `In-Reply-To` / `References` when the read payload includes them.
3. Only then broaden to INBOX / All Mail. Do not repeat the same query more than twice.
4. Send/reply → confirm with user, ensure `email_tool` loaded, call tool (Many shows approval card for send/reply).

## Pinned email
- Pin ids may be Dome cache ids (`emsg-…`) or IMAP uids. Both are valid for `email_read`.
- Pass `folder` (and `accountId` when the pin meta has it) from mentioned-sources. Do not guess INBOX if meta says otherwise.

## Mentioned people → `to`
- When Source has **mentioned-people** with `email:addr`, use that address as `to` (do not invent).
- If the person has no email identity, ask once for the address before calling `email_send`.

## Memory (domains/email.md)

- **Do** call `remember_fact` with `domain=email` for VIP prefs, reminder SLAs, and durable commitments (“follow up Friday”).
- **Don't** store message bodies, passwords, or every list/search result.
- Prefer Domain memory (email) when triaging or drafting follow-ups.
