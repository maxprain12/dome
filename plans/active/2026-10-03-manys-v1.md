# Many’s v1 — ejecución cloud multiusuario

Plan versión 1 · 2026-10-03 · repositorios Dome y Dome Provider.

El usuario ha autorizado implementar y se encargará de validar staging. La flota Linux y gVisor no se han desplegado desde esta tarea.

## Decisiones

Cada cuenta es un tenant. Many, conversación, tarea e intento son entidades diferentes. Provider valida solicitudes OAuth; procesos worker ejecutan el harness de Dome a través de un artefacto portable. Ninguna ejecución larga depende de una petición HTTP ni de Electron abierto. CopilotKit Intelligence no forma parte del runtime.

Postgres mantiene trabajo, sesiones, propuestas, recibos, permisos, reservas de créditos, asignación de ordenadores y eventos. Redis no autoriza consumo ni contiene la única copia del trabajo. La biblioteca sigue siendo Domain Sync; no existe una segunda biblioteca de Many’s. S3 guarda los entregables.

Las transacciones establecen rol y tenant de forma local a la conexión. RLS y claves compuestas impiden relaciones entre usuarios. La cola reclama con `SKIP LOCKED`, turnos por usuario, fencing, heartbeat y recuperación únicamente de leases vencidos. Defaults: un intento activo por Many, dos por cuenta y 32 globales; cuatro workers en el manifiesto inicial.

Cada acción revisada conserva parámetros, cuenta, conexión, versión del destino, revisión de permisos, caducidad y digest. La operación tiene identidad por paso, no por igualdad de parámetros. Una operación enviada con resultado incierto exige reconciliación antes de continuar. No se repite automáticamente.

## Entrega por etapas

| Etapa | Implementación |
|---|---|
| Contratos y aislamiento | Esquema `manys`, roles sin bypass, RLS, relaciones compuestas, OAuth y rutas `/api/v1/manys` |
| Cola y consumo | Claim transaccional, turnos, leases, límites, reservas y liquidación compartidas con chat |
| Tareas y aprobaciones | Checkpoints, sesiones, preguntas, pausa, continuación, cancelación, propuestas exactas y recibos |
| Runtime y vault | `@dome/manys-runtime` 0.1.0/protocolo 1, harness portable, adaptadores de contexto, CAS, conflictos, outbox y entrega S3 |
| Flota y gateway | Supervisor privado, OpenBot fijado, credenciales individuales, gVisor obligatorio, volúmenes persistentes y takeover |
| Interfaz y retirada | Pestaña Many’s, ordenador lateral, borradores, mensajes durables, revisiones, recurrencias y configuración; rutas anteriores migradas |

La migración SQLite 81 elimina datos operacionales de agentes/workflows/automatizaciones y conserva biblioteca, proyectos y conversaciones/runs del Many local. Provider retira el dominio sync `agents`. Marketplace no carga ni muestra esas categorías. Los stages de pipelines delegan a un Many cloud o al Many local.

- [OpenBot b6932d3](https://github.com/CopilotKit/OpenBot/tree/b6932d31a8d6e7896c15139dfc27a6c6911deb27): navegador, archivos y terminal. Se mantiene su MIT; el Dockerfile añade endpoints acotados de intervención humana y exportación de archivos.

Revisión estática de las referencias; no se ejecutaron sus suites. El runtime de Many’s usa código de Dome.

## Validación

Pruebas locales: suite real PostgreSQL con conexiones concurrentes, aislamiento RLS, FK, reparto, fencing, doble aprobación, caducidad/revocación/cambio de cuenta, recibos idempotentes, recurrencias y conflictos del vault; prueba de harness con servidor de modelo simulado y reinicio de sesión; prueba SQLite de conservación de datos.

Ejecutar `pnpm run test:manys` y los controles de AGENTS.md en Dome. Provider incluye la suite `lib/manys/postgres.test.ts`, habilitada únicamente por `MANYS_TEST_DATABASE_URL` contra una base de pruebas migrada. Guía de operación y validación de flota en Provider: `docs/manys.md`.

Staging pendiente del usuario: credenciales reales, OAuth renovado, Desktop cerrado → tarea cloud → vault → reconexión, gVisor/navegador/terminal, firewall, caída de Redis/host y prueba de carga. El código permanece desactivado por defecto mediante `MANYS_ENABLED=false` hasta preparar roles e infraestructura.

## Alcance de v1

Las acciones externas se realizan en el ordenador, mediante propuestas revisadas. Los conectores directos que no tienen adaptador rechazan la ejecución. No se incluyen voz, Slack, cooperación automática entre Many’s, paneles especializados ni Companion. Un host perdido no reasigna un volumen local a otro host: conserva la asignación y bloquea el acceso hasta recuperar el host. No se ha afirmado capacidad de producción sin las mediciones de staging.
